# Notification Center — EXPERIMENTAL (reversible)

نظام إشعارات داخلي بسيط بين المدير والمندوب. **ميزة تجريبية**، مصمّمة لتُحذف بالكامل
دون أي أثر على بقية النظام.

## ماذا تفعل

- **المدير**: زر جديد "الإشعارات" في لوحة التحكم → صفحة لإنشاء إشعار (نوع، عنوان، نص،
  المرسل إليه، عميل اختياري، منتج اختياري) ورؤية حالات كل الإشعارات
  (جديد / تمت القراءة / تم التنفيذ).
- **المندوب**: أيقونة جرس صغيرة في ترويسة الكتالوج مع Badge أحمر للإشعارات الجديدة.
  الضغط يفتح نافذة جانبية (وليست صفحة). فتح الإشعار:
  - رسالة / إعلان → قارئ داخلي.
  - كشف حساب → قارئ كشف حساب داخلي (من حقول الإشعار — لا يوجد جدول عملاء).
  - منتج / عرض → يفتح صفحة المنتج.
- عند فتح الإشعار تتحول حالته إلى **تمت القراءة**، ويظهر شريط "تم فتح هذه الصفحة من
  إشعار" مع زر **تم التنفيذ** الذي يحوّل الحالة إلى **تم التنفيذ** فتختفي من قائمة الجديد.
- التحديث عبر **Polling كل 30 ثانية** (بدون WebSocket).

## قاعدة البيانات

جدول جديد واحد فقط: `notifications`. يُنشأ تلقائياً عند أول تشغيل من
`server/src/notifications/`. لا يُعدَّل أي جدول آخر.

## كيفية الحذف الكامل (Rollback)

1. احذف مجلد الواجهة: `src/features/notifications/`
2. احذف جسر المسار: `src/routes/notifications.tsx` (وأعد توليد `routeTree.gen.ts`
   بتشغيل `npm run dev`/`npm run build`).
3. احذف مجلد الخادم: `server/src/notifications/`
4. أزل الأسطر المعلَّمة `[notifications-feature]` في:
   - `server/src/app.ts` (سطرا import + register)
   - `src/routes/admin.tsx` (زر "الإشعارات")
   - `src/routes/catalog.tsx` (أيقونة الجرس `<NotificationBell />`)
   - `src/routes/product.$id.tsx` (شريط المصدر + قراءة `search.notif`)
   - `vite.config.ts` (`/notifications-api` في قائمة الـ proxy)
5. (اختياري) أسقط الجدول: `DROP TABLE notifications;`

بعد ذلك يعود النظام إلى حالته الأصلية تماماً.
